## 2. 各维度评价

### 2.1 功能完整性 —— 70%

**已完成（对照 README M0–M7 与方案 3.4）：**
- M0 契约层：IR v0 三层结构（L0 内容块 / L1 规范请求 / L2 会话缓存上下文）完整，v3 关键常量齐备（4 断点上限、20-block 回看窗口、非单调模型阈值表）
- M1 可观测：方案 3.3 五项必暴露指标全部落库（命中率 / 注入 token / 重放 token / 丢弃参数 / 降级路径），OpenAI 折扣按代次（v3 修正已落实），对账口径正确（prompt_tokens - cached_tokens）
- M2 状态层：会话表 + TTL + previous_response_id 反查 + TRACK04 task-id 单键兜底（find_active_by_task）+ 重放起点规则（window/full）
- M3 适配层：三对 adapter 双向转换 + 丢弃参数/降级路径记录；max_tokens=0 预热语义保留
- M4 网关：三端点路由 + 限流（Semaphore=2）+ 预热单独路径 + 预热拒绝条件校验（v3 已核实的 5 条）+ mock/真实双模式
- M5 实验层：11 组对照（含 v3 重写的 G2 三档：512/1024/4096）+ 先串行预热再计量（v3 方法学前置）+ 盈亏平衡计算
- M6 面板：缓存前缀可视化 + 记忆勾选裁剪 + v3 安全骨架五项（127.0.0.1 / 随机端口 / Host 校验 / 一次性 token / 脱敏）
- M7 交付层：`docs/量化取舍文档.md` 质量高，结论、断点布局、有损字段清单、对照表齐全

**缺失/未完成：**
1. **真实上游不渲染 cache_control 断点（最关键缺口）**：`AnthropicUpstream.complete()` 构造请求时完全不带 `cache_control` 字段，IR 里的 `cache_control: list[int]` 断点下标没有任何下游消费者。4 断点布局（3 固定 + 1 滚动）目前只存在于 mock 模拟中——真实 API 实验跑不出方案要的断点效果
2. **网关侧没有记忆注入管线**：M6 面板裁剪的记忆写在 `session.meta["memories"]`，但网关 `handle()` 从不读取它注入 IR 请求；「记忆注入 + 幂等去重」只在实验脚本的 mock builder 里存在，线上链路是断的
3. **SSE 流式透传未实现**：README 声称「SSE 透传」，但 `stream=True` 解析后无任何处理，`BaseAdapter.stream_chunks_from_ir` 返回空列表且无人调用，网关永远返回非流式 JSON
4. 工具 ID 映射表（方案 9/3–9/6 产出物）无独立文档/模块（目前仅靠 IR 透传 id，OpenAI `call_xxx` ↔ Anthropic `toolu_xxx` 风格差异无映射层）
5. 能力矩阵 v0（可配置、注明数据日期）未见独立产物
6. 真实验证项全部未做（README 已自知）：D2 prev_id 冲突、20-block 真实边界、count_tokens RTT、4096 档大块复测

### 2.2 代码质量 —— 85%

**优点：**
- 模块边界清晰，注释与方案条款互相引用（每条关键设计都标注了方案出处），可维护性好
- SQLite 短生命周期连接 + WAL + 自动迁移补列，工程细节扎实
- mock 上游的缓存语义（阈值查表、回看窗口、预热写条目）准确对齐 v3 修正口径

**问题：**
1. `upstream.py` 的 `OpenAIUpstream.complete()` 有一段死代码：先用 `OpenAIChatAdapter.from_ir()` 构造 payload，随后立即被手工构造的 payload 覆盖（第 88–96 行白费）；且手工 payload 不带 tools、丢弃 tool_use 块
2. `AnthropicUpstream.complete()` 只取响应第一个 content block 的 text，真实链路 tool_use 块丢失——真实模式下工具调用往返会断
3. **盈亏平衡误判 bug**：`break_even_rows()` 中 G1/G2-4096/G4 三组 creation_cost=0、saving=0，`0 >= 0` 判定为「回本」——CSV 里这三组显示「回本」具有误导性（量化文档表格中正确地写成了「—」，代码与文档不一致）
4. `_estimate_injected_tokens` 用 `len(text)` 字符数充当 token 数；`_estimate_replay_tokens` 用「轮数 × 120」硬编码——作为占位可接受，但埋点数据的 ②③ 两项目前是示意值而非真实 token 口径
5. 网关 `handle()` 的异常一律转 502，mock 模式下也会吞掉 adapter 层的解析错误，排障不友好

### 2.3 文件组织 —— 90%
