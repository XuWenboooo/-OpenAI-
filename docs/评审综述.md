# 协议转换课题 · 评审综述

> 本综述对照《协议转换课题_执行方案 v3》编写，供评审者快速把握项目全貌。分三部分：**一、功能**（提示要求实现的功能）、**二、完成度**（实现程度与已完整落地部分）、**三、不足之处**（局限与待改进项）。

## 一、功能（该提示所要求实现的功能）

本课题的核心目标：在 **OpenAI Chat Completions / OpenAI Responses / Anthropic Messages** 三套大模型 API 协议之间，建立一套统一的**中间表示（IR）契约**与**运行时转换网关**，并通过**提示词缓存（Prompt Caching）断点布局**最大化缓存命中率、降低重复前缀的 token 成本。执行方案 v3 要求实现的功能如下：

### 1. 统一 IR 契约（M0）
- 定义跨协议的中间表示 `IRRequest / IRResponse / ContentBlock / IRMessage / IRUsage / IRToolCall`。
- 覆盖三种内容块类型：文本、思考（thinking）、工具调用（tool_use），并承载缓存控制元数据。

### 2. 三对双向 Adapter（M1）
- `AnthropicAdapter` / `OpenAIChatAdapter` / `OpenAIResponseAdapter`，各自实现：
  - `to_ir`：上游请求 → IR
  - `from_ir`：IR → 上游响应
  - `ir_to_payload`：IR → 真实上游请求体（含 `cache_control` 断点渲染）
  - `response_to_ir`：真实上游响应 → IR（保留全部内容块）
  - `stream_chunk`：IR → 流式 chunk
  - `parse_usage`：用量解析（含缓存创建/命中 token）

### 3. 网关运行时转换（M3）
- HTTP 网关接收任一协议请求，转换为 IR、路由到目标上游、再转回原协议响应。
- 提供 `chat/completions`、`responses`、`messages` 三个端点。
- 限流（并发 2，硬件友好）、预热请求单独路径、拒绝条件校验（缺 `max_tokens` 等非法请求直接 400）。

### 4. 提示词缓存断点布局（核心修正）
- 4 断点布局：**3 固定断点 + 1 滚动断点**（system[0]、system[-1]、历史静态段末、易变内容前的滚动尾部）。
- 渲染顺序 `tools → system → messages`，易变内容（时间戳 / request-id）放最后，断点前任意字节变化都会使其后缓存失效。
- 预热请求只打 system 断点，避免占位消息污染缓存。

### 5. 多轮会话状态层（M2）
- `SessionStore`：维护 `previous_response_id` 链路、会话 TTL、轮次记录、task-id 兜底。

### 6. 记忆注入管线（M6 → 网关）
- 编排面板裁剪的记忆写入会话 meta，网关在请求时注入 system 尾部，并按文本**幂等去重**。

### 7. 可观测性埋点（M4）
- 北极星五项指标：缓存命中率、注入 token 数、重放 token 数、被丢弃参数、降级路径。
- 落库到本地 SQLite（`MetricsStore`）。

### 8. SSE 流式透传（M3 延伸）
- 网关识别 `stream=true`，上游分块产出、网关逐块转协议后透传 `text/event-stream`。

### 9. 量化对照实验（M5）
- 三组变量 × 模型阈值对照：**更新频率 × 缓存位置 × 粒度**，共 11 组。
- 先预热再计量，输出命中率与溢价/盈亏平衡。

### 10. 编排面板与安全骨架（M6）
- Web 面板：缓存前缀可视化、记忆裁剪、Host 头校验、token 校验、敏感信息脱敏。

## 三、不足之处（局限与待改进）

### 1. 真实 API 验证缺失（最关键）
- 所有实验与断点布局均在 **mock 模式**下完成，未在真实 Anthropic / OpenAI API 上跑通。
- 待验证项：D2 `previous_response_id` 冲突、20-block 窗口真实边界、各模型阈值逐模型核对、`count_tokens` RTT 成本、4096 档大块复测。
- 影响：缓存命中率、盈亏平衡等核心结论目前是**仿真值**，未被真实用量数据证实。

### 2. M7 交付物缺失
- 工具 ID 映射表、能力矩阵 v0 两个文档尚未产出（执行方案 9/3–9/6 主链路阶段的交付物）。

### 3. Token 计量为示意口径
- 注入 token / 重放 token 目前按**字符数**估算（已在代码与文档标注「示意口径」），非真实 tokenizer 计数；`count_tokens` 的真实 RTT 成本未测量。

### 4. 评测为自评、非独立验证
- 完成度评测由本项目的实现方自测自评，缺少第三方独立核对；mock 模式下的指标可能高估真实收益。

### 5. 流程与治理项未闭环
- `ir-schema.md` 三方签字冻结未完成。
- **Session 边界三耦合点（重放起点→缓存前缀 / 记忆回流幂等 / prev_id 状态键）已按 v3(1) 3.9.1 做成可切换配置**，并非「未做」；默认假设值（task-id 单键 / 全量重放 / ttl+archive）可独立运行，仅待 TRACK 04 在参数层面正式签字确认——届时改配置即可重验，不返工。其中「重放→缓存前缀」此前仅存方法未接线，已接入网关前缀构造。
- 分工会未确认自仓库 PR 的考核口径。
- PR 尚未提交（代码侧已就绪，等仓库可见性确认）。

### 6. 安全骨架未硬化
- M6 面板的安全为骨架级：Host 校验放行 localhost、token 校验较基础、脱敏仅覆盖部分字段；距生产级仍有差距。
