## 0. 北极星问题（一句话回答）

**在 OpenAI Chat / OpenAI Response 与 Anthropic 之间做记忆注入，缓存命中的损失到底是多少？哪种注入策略最省钱？**

- **损失来源**：记忆注入的内容 / 顺序 / 粒度一旦变化，Anthropic 前缀缓存整段失效（断点前任何字节变，其后全失效），命中率从 100% 掉到 0%，且不报错。
- **最省钱的策略**：**会话开始注入一次并锁死（确定性序列化）**——预热后保持 100% 命中；每轮动态注入写入成本约为它的 1.8 倍（本组数据 0.0422 vs 0.0233 美元），且无法回本。

## 1. 实验设计（方案 3.6 三维度对照 × 模型阈值，v3 修正版）

**方法学前置（官方并发约束）**：Anthropic 缓存条目在**首个响应开始后**才可被其他请求使用。所有对照组**先串行预热（max_tokens:0 建立缓存条目）再计量**，预热不计入统计；否则并行打相同前缀的首批请求必然全 miss，数据全废。

| 组 | 维度 | 策略 | 预期（v3） | TRACK01 |
|---|---|---|---|---|
| A | 更新频率 | 基线：不注入记忆 | 预热后全命中，但记不住偏好 | — |
| B | 更新频率 | 会话开始注入一次并锁死 | 预热后全命中（推荐候选） | L3 无条件注入 |
| C | 更新频率 | 每轮动态注入 | 命中率断崖→0（每轮新前缀） | L1/L2 按需召回 |
| D1 | 位置 | 记忆放前缀头部（system 后） | 命中稳定 | L3 最佳落点 |
| D2 | 位置 | 记忆放消息流尾部（append） | 缓存层命中，但 previous_response_id 冲突 | L1/L2 尾部 |
| G1 | 粒度 | 单块约 300 token（< 512） | 全档低于阈值→静默不缓存 | — |
| G2 | 粒度 | 4×512 每块后断点（用满 4 个），Opus5/512 档 | 断点1（512）即达标，全命中 | — |
| G2-1024 | 粒度 | 同 4×512，Opus4.8/1024 档 | **断点2 累计 1024 达标→命中（v3 推翻 v2 块级错误）** | — |
| G2-4096 | 粒度 | 同 4×512，Opus4.5/4096 档 | 断点4 累计 2048<4096→全程静默 | — |
| G3 | 粒度 | 单块 2048 大块 | 512/1024/2048 档稳定命中（4096 需 4096+ 复测） | — |
| G4 | 粒度 | 30 条细粒度，仅尾部 1 滚动断点 | 上轮写入距新断点超 20 块→回看失效全部重算 | — |

**关键语义（v3 修正）**：最小可缓存长度按**断点处累计前缀**判定，前缀累加——**分块不重置阈值，但会推迟达标时点**；同总量下单块优于多块。数据口径：mock 上游（离线演示，`稳定前缀 = system + messages[:-1]`，累计 ≥ 模型阈值且块数 ≤ 20 才缓存）。

## 3. 核心结论

1. **更新频率是决定性变量**：锁死（B）≈ 基线（A）≈ 预热后 100% 命中；每轮动态（C）命中归零、写入成本最高且无法回本。**「会话内锁死 + 确定性序列化」是唯一不伤缓存的方式**（TRACK 01 业界基准：L3 无条件注入作稳定前缀，L1/L2 工具化按需召回）。
2. **位置影响次要**：头部（D1）与尾部（D2）缓存层命中率相当；D2 存在 previous_response_id 语义冲突与注意力偏移，**优先选头部注入**。
3. **粒度：分块不重置阈值但推迟达标**（v3 修正）：同 4×512 块，512 档（Opus5）与 1024 档（Opus4.8，断点2 累计 1024）都命中，仅 4096 档（Opus4.5，断点4 累计 2048<4096）静默不缓存——**阈值必须逐模型查表**（4.5/4.6=4096，4.7=2048，4.8=1024，5=512），单块 2048 在多数档位稳定命中。
4. **预热是实验前提**：缓存条目首个响应后才可用，不预热直接放量 → 首批请求全 miss，数据失真。
5. **盈亏平衡**：稳定策略预热后每轮命中、写成本归零（预热一次性写入不计入计量），1 次命中即回本；动态注入无法回本。

## 4. 断点布局（方案 1.3 图 2 / 3.7 · 官方 4 断点硬上限）

**每请求最多 4 个 cache_control 断点，第 5 个返回 400**——"历史每 N 块插断点"不可行。

| 断点 | 位置 | 说明 |
|---|---|---|
| 1 | tools 后 | 固定分层断点 |
| 2 | system 后 | 固定分层断点（记忆注入稳定落点） |
| 3 | 历史静态段后 | 固定分层断点 |
| 4 | 滚动尾部 | 跟随每轮最后一块（长对话靠它 + 20-block 回看覆盖） |

渲染顺序 tools → system → messages，易变内容（时间戳/request-id）放最后；断点前任意字节变则其后全部失效。

> 落地：`AnthropicAdapter.ir_to_payload` 已按此渲染 cache_control（3 固定 + 1 滚动）；预热请求 `warmup=True` 时只打 system 断点、不打占位消息（方案 3.7 断点位置陷阱）。

## 6. Token / 缓存语义对照表（方案 3.5 · 课题点名的坑）

**缓存 token 归属（三家三种算法）**

| 协议 | input token 构成 |
|---|---|
| Anthropic | input_tokens **不含**缓存读写；总数 = input + cache_read + cache_creation |
| OpenAI Chat | prompt_tokens **包含**缓存部分；cached_tokens 是其子集 |
| OpenAI Responses | input_tokens + input_tokens_details.cached_tokens |

⚠️ 不能直接把 Anthropic 的 input_tokens 塞进 Chat 的 prompt_tokens（对账全错）。本实现已修正：OpenAI Chat 解析 `input_tokens = prompt_tokens - cached_tokens`。

**计费口径与 TTL（双重不对称，v3 按代次修正）**

| 维度 | Anthropic | OpenAI |
|---|---|---|
| 写入 | 5 分钟档 1.25x / 1 小时档 2x | 无写入溢价 |
| 读取折扣 | 0.1x（省 90%，全系一致） | **按代次：GPT-4o/o 系省 50% / GPT-4.1 系省 75% / GPT-5 系省 90%** |
| TTL | 5 分钟 / 1 小时 | 默认 5–10 分钟，2026 起可选 24 小时 |
| 触发 | 显式 cache_control 断点（每请求最多 4 个） | 自动（prompt ≥ 1024 token，按 128 递增） |

两个必须写进对照表的不对称：① TTL 上限差一个量级——**Responses→Anthropic 方向 24h 保留语义无法表达，只能降级为 1h 并标注损失**；② 成本模型不可直接折算（本实现 `estimate_cost_usd(u, protocol, model)` 已按协议+代次区分读写费率）。

## 7. 预热请求与弹网页安全（方案 3.7，v3 修正版）

- **预热请求（max_tokens:0）**：官方支持用法。行为：读入提示并在断点处写缓存，不生成输出即返回（content 空数组、stop_reason=max_tokens、usage 完整且 output_tokens=0）。**拒绝条件**：不能同时带 stream / extended thinking / structured outputs / tool_choice={type:tool|any}（否则 400）。**断点位置陷阱**：cache_control 必须打在共享前缀末尾（system prompt），不能打在占位 user 消息——占位消息需非空（官方示例 "warmup"）。转换层已开单独路径（`_is_warmup` + `_validate_warmup`），并拒绝违反条件的请求。
- **保活**：人工交互耗时不影响 TTL；危险的是主循环两轮间空闲超 5 分钟 → TTL 过期重写。5 分钟档需每 5 分钟预热一次，间隔更长用 1 小时档。
- **弹网页安全（v3 删除 PKCE/state——无 OAuth 流程，替换为对症措施）**：绑定 127.0.0.1；随机端口 + **Host 头校验**（只接受 127.0.0.1:端口，防 DNS rebinding）；**URL 一次性 token**（`/?t=随机串`，服务端校验后才返回页面，防扫端口）；**敏感信息脱敏**（邮箱/手机/证件打码 + 截断，完整内容需显式点开）。

## 8. 有损字段清单（转换层必须处理的降级）

| 源协议字段 | 目标侧处理 | 风险 |
|---|---|---|
| `previous_response_id` | 状态层重放历史（Anthropic 无服务端状态） | 会话丢失/重复注入 |
| OpenAI `tool_calls` id | 映射为 tool_use id | 工具结果回填错位 |
| Anthropic `cache_control` | IR `cache_control` 透传（≤4 断点） | 断点布局错→缓存失效/400 |
| `thinking` / `signature` | thinking 块透传 | 签名丢失→思考链无法续 |
| 结构化输出约束 | 显式降级策略 + 告警（dropped_params） | 输出格式不保证 |
| MCP 工具语义 | 降级为 function | 语义保真损失 |
